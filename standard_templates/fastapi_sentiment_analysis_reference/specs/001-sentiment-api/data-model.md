# Data Model: Sentiment Analysis API

## SentimentRequest

- **Purpose**: Represents the client payload submitted for sentiment analysis.
- **Fields**:
  - `text`: required string; must be non-empty after trimming; must not exceed
    the configured maximum character length.
  - `language_hint`: optional string; advisory only; may be used for diagnostics
    or future extensions but does not override core inference behavior in the
    initial release.
  - `request_id`: optional string; caller-supplied correlation identifier if
    provided, otherwise generated by the service.
- **Validation rules**:
  - `text` MUST be present.
  - `text` MUST contain at least one non-whitespace character.
  - `text` MUST fall within the configured size limit.
  - Unknown fields SHOULD be rejected to keep the contract strict.

## SentimentResult

- **Purpose**: Represents the successful result returned to the caller.
- **Fields**:
  - `request_id`: string correlation identifier.
  - `label`: normalized sentiment category returned to consumers.
  - `confidence`: numeric confidence score for the selected label.
  - `model_name`: string identifying the approved model used for inference.
  - `input_size`: integer count of processed characters.
  - `processed_at`: timestamp indicating when the result was produced.
- **Validation rules**:
  - `label` MUST be one of the documented contract values.
  - `confidence` MUST be between 0 and 1 inclusive.
  - `model_name` MUST equal the configured default model unless an approved
    governance change is introduced.

## ErrorResponse

- **Purpose**: Represents a structured failure returned to the caller.
- **Fields**:
  - `request_id`: string correlation identifier.
  - `error_code`: stable machine-readable code.
  - `message`: user-facing error summary.
  - `details`: optional structured context for validation failures or known
    error conditions.
  - `retryable`: boolean indicating whether retry may succeed without changing
    the request.
- **Validation rules**:
  - `error_code` MUST use documented stable values.
  - `message` MUST be safe for client display and MUST not contain stack traces.

## ReadinessStatus

- **Purpose**: Represents service readiness for traffic.
- **Fields**:
  - `status`: readiness state value.
  - `model_loaded`: boolean indicating whether the sentiment model is available.
  - `version`: service version string.
  - `checked_at`: timestamp of the readiness evaluation.
- **State transitions**:
  - `starting` -> `ready` when configuration is valid and the model is loaded.
  - `starting` -> `not_ready` when startup checks fail.
  - `ready` -> `not_ready` if model availability or critical dependencies fail
    after startup.

## ServiceState

- **Purpose**: Internal application state used by the service layer and
  readiness checks.
- **Fields**:
  - `model_pipeline`: loaded inference pipeline instance.
  - `model_name`: configured HuggingFace model identifier.
  - `max_input_chars`: configured payload limit.
  - `startup_completed`: boolean startup flag.
  - `last_model_load_error`: optional summary of the latest model load failure.
- **Relationships**:
  - `ServiceState` supplies runtime context for `SentimentResult` production and
    `ReadinessStatus` evaluation.
